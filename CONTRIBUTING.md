# Contributing

Contributions that strengthen the framework are welcome — additional use-case patterns, control refinements, measurement improvements, and corrections from practitioners running agents in real regulated environments.

## Ground Rules

1. **Vendor neutrality is non-negotiable.** Contributions must not promote, assume, or disparage specific platforms. Platform-specific implementation notes belong in clearly labeled appendices, mapped back to the neutral pattern.
2. **Synthetic content only.** No real organizational data, metrics, architectures, or identifiable incident details — including your own employer's. Sanitize to the pattern level.
3. **Practitioner evidence over opinion.** "This control failed in practice because…" outranks "I think…". Say which environment class your experience comes from (healthcare, financial, public sector) without identifying it.
4. **Keep the discipline.** New use cases follow the intake structure: problem, capability, exclusions, risk profile, metrics, pilot design. New controls state the threat they answer.

## Process

- Open an issue first for substantial changes (new documents, structural shifts) using the **Use Case Request** or **Risk Review** template
- Pull requests use the provided template; one logical change per PR
- Markdown, tables for matrices, Mermaid for diagrams — match the existing style
